# Read-only cached-result artifact viewer

Owner-requested local plotting is separate from the synthetic dashboard and from INT-01/project operations. The optional Windows `native_results` example reads an explicitly selected version directory's existing `manifest.json`, `results/calc_output.json` and `results/source-units.json`. It never opens ETABS, recalculates, writes a version/database/artifact, restores a prior project or starts a sidecar. No real input is included in this repository or default tests.

```powershell
cargo run --release --locked --offline --features cached-results,webview --example native_results -- '<version-directory>'
# Non-graphical local schema/identity/unit check:
cargo run --release --locked --offline --features cached-results,webview --example native_results -- '<version-directory>' --check-only
```

Dependencies `ext-calc` and `ext-core` use the same reviewed EtabExtension pin `9eb1c8792a1d41f3f81c60428afe89f1655782ba` as `ext-e2k`. The code deserializes authoritative `CalcOutput`, `VersionManifest` and `SourceUnitMetadata`, reuses source-unit validation and projects cached fields for presentation. It does not copy or invoke calculation algorithms. No `ext-api`, `ext-render`, Deno/V8 or Typst dependency is added to this example; #18's separate backend CRT/package hold remains unresolved. First metadata resolution required updating futures-channel to0.3.34 to match the existing futures-util optional channel requirement; other previously locked choices are retained where compatible.

## What is actually plotted

- Cached wind drift: chosen direction/group/output case, **stored positive and negative envelope fields as written**, with the cached allowable ratio. No new absolute envelope, maximum, sign change or threshold is calculated.
- Cached signed story shear: the selected existing case profile's Vx or Vy values. Labels preserve canonical source units; the initial adapter supports confirmed kip/ft canonical artifacts and rejects other unit contexts instead of guessing conversions.
- Story categories retain the cached explicit order; duplicate/unknown story keys are refused. Missing values remain null/gaps, never synthesized zeros. No unreviewed `ext-render` chart-spec or static-chart parity claim.
- Native table and both plots consume one packet. Typed IPC is scoped to the snapshot fingerprint and monotonic generation; unknown fields, plots/stories and retired messages are refused. Selection-only updates preserve chart zoom/legend. This is cached **story-label selection**, not a structural EntityKey/3D/project source-fidelity proof.

## Identity and safety limits

Reject `.partial`, branch/version mismatch, missing/conflicting unit provenance, missing/duplicate story order, non-finite plotted values and duplicate selected rows. Reads are bounded64MiB per artifact. A combined fingerprint includes manifest/result/unit bytes; reread each input and refuse an observed change while loading. The app owns only its in-memory snapshot; files are not changed and file handles close after reads.

**Analysis freshness is not proven by this fingerprint.** It identifies the bytes read, not that results match the latest source model or were generated by the pinned calculation engine. The UI always identifies cached/unverified freshness, additionally surfaces a manifest not marked analyzed and never labels this as a current validated analysis. Legacy/unsupported/missing cache data produces an error, not plausible fabricated curves. Project operations, source-model provenance, committed version switching and authoritative calculation/static-chart parity remain separate gates.

Initial loading is synchronous before creating the native window; there is no async/cancel/responsiveness claim. Normal tests use independently authored small DTO files in owned temporary directories. Private inputs, source hashes, counts, warnings, plots and timings must stay local; no public private-derived evidence or automatic smoke export is provided. The default synthetic dashboard remains separate.

Native window/egui persistence is explicitly disabled and case/group choices are cached once per input snapshot. Artifact paths resolving outside the selected directory are refused. The freshness warning is visible in both native controls and the chart page.

## Owned public fixture probe

```powershell
& '<native_results-executable>' --public-fixture-probe
```

This mode accepts **no input path**. It constructs only the embedded independently authored fixture in an owned TempDir, reads it through the same authoritative DTO adapter, verifies unchanged bytes and emits `packet.json`/`status.json` in a fresh owned temporary report directory. Its data-free stdout receipt identifies that report directory and the input directory, which has been removed when the process exits. There is no export mode for user-selected artifacts.

An external test can feed that emitted public packet into the HTML regression:

```powershell
node tests/chart-layout/cached.cjs --public-probe='<owned-public-report-directory>'
```

The test requires the known public fixture identity/titles and exact authored values, order/nulls/signs before declaring PASS. It creates/closes only its headless browser, verifies process exit, and does not certify native physical interaction. Copy public evidence before cleaning the specific owned report directory; never delete a supplied version or shared browser profile. The separate `--check-only` path only validates locally and never emits plots/data.

## Resource and validation status

No ETABS/process worker is created. Native window teardown uses the existing shared Wry transport's controller-close path. This is not SDK-confirmed browser-group termination or a20-cycle lifecycle proof; those remain open under #8/#28. Test code releases its owned temporary directories; chart HTML regression tests close their owned browser/server and verify browser process exit. Never kill owner/shared WebView processes or clean shared/private Cargo artifacts.

Implementation is experimental and draft. Schema/DTO/native/WASM/Clippy/Release and local read-only checks must be recorded at their actual source heads before any PASS claim. No migration readiness, engineering recalculation, production modification or merge is implied.
